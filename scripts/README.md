# scripts/ — `pg_check.py`, `cadence_check.py`, `upgrade_workspace.py`

Three pure-standard-library scripts: Python ≥ 3.10, no packages, Windows/macOS/Linux, UTF-8. The skills run them from the project root and read what they print, never their source.

`pg_check.py` is the pure-standard-library reinforcement of the Forge's "authority by construction" rule (`docs/METHODOLOGY.md` §3b.5): it reads `g2g/07_theory/` and reports every state the protocol forbids. It runs at the start of every Forge round (g2g-forge step 1), as `--pregate` on each candidate before its verifier is dispatched (g2g-forge step 5), and in the g2g-status graph-health section; g2g-go's preflight only reports whether it can run. **If it does not pass, work does not start.**

## CLI

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/pg_check.py" g2g --report                                  # round start and g2g-status; cwd = the user's project root
python "${CLAUDE_PLUGIN_ROOT}/scripts/pg_check.py" g2g --pregate P-0012                          # g2g-forge step 5: the candidate(s) about to go to a verifier
python scripts/pg_check.py <programme_root> [--report] [--regen-index] [--fill-sha] [--json] [--version]   # general form (repository checkout / development)
python scripts/pg_check.py <programme_root> --pregate P-ID [P-ID …] [--json]
```

`${CLAUDE_PLUGIN_ROOT}` is the installed plugin's root (a repository checkout's root when developing). `<programme_root>` is the folder containing `g2g/`, the `g2g/` folder itself, or `g2g/07_theory/` — the skills pass `g2g` with cwd = the project root. `--version` prints the script version and is g2g-go's script-availability test. Without flags it only checks and prints one line per violation: `CODE  file  message` (file relative to the programme root). `--pregate P-ID [P-ID …]` runs only the pre-gate registration check (codes below) on the named candidates — each must be a `proposed` node in `candidates/` — and prints its findings in the same form; it runs alone (not with `--report`, `--regen-index` or `--fill-sha`), writes nothing, and with `--json` gives `pregate`, `findings`, `finding_count`, `exit_code`. Bold used for emphasis is reported like a bold definition: the orchestrator reads the findings and decides whether the candidate goes back to its deducer. `--report` appends a health summary (counts by status — split into current revisions, i.e. what a bare ID resolves to, plus candidates still under the gate, and historical ones — kind and empirical status; revocations and revisions by reason category, with gate misses on their own line; axiom and conjecture statuses, support closure of every current theorem-kind node, cadence hints from `forge-log.md` with defaults K=10 / M=4 / T=25, the theory-tribunal hint counting current verified nodes; informational findings). The forge-log reader takes the round number **only from entry title lines `## Round n`** (never from prose — "macro audit at round 4" in a Cadence line does not count) and the submitted / passed counts from the `a / b / c` triple of each "Submitted" line; when the log's cumulative passed count is below the number of `verified` nodes on disk (typically 0 / 0 against freshly landed nodes) the report adds one line, `(forge-log has no entry for the nodes on disk yet — write the round entry)`. `--regen-index` rewrites `graph-index.md` from the node files (columns: ID · one-liner · kind · status · empirical_status · predecessors · A/D/DA used · verification · layer). `--fill-sha` writes `content_sha` (first 12 hex of sha256 over the Statement + Derivation texts, line endings normalised) where missing or stale — into **both** `propositions/` and `candidates/`: a candidate's digest is fixed before the gate, so a Statement or Derivation that changes between submission and landing shows up as `STALE_SHA` once the file is in `propositions/` (tamper evidence across the gate); the `MISSING_SHA` / `STALE_SHA` checks themselves are raised for `propositions/` only. `--json` emits everything as one JSON document (`report` is `null` unless `--report` is also given). Only `--regen-index` and `--fill-sha` modify files; nothing is ever deleted. Output is UTF-8: the script switches stdout / stderr to UTF-8 itself (no `PYTHONIOENCODING` needed on Windows); if that fails the report falls back to ASCII glyphs (`->`, `-`, `,`).

## Exit codes

Exit code = number of violations (0 = clean), capped at 255; with `--pregate`, the number of findings for the named candidates, capped likewise. `2` = usage / IO error (no `07_theory/` found, unreadable file, a `--pregate` ID that is not a proposed candidate) — distinguishable from two violations by the `error:` line on stderr and the empty stdout.

## Violation codes (counted)

| Code | Condition | Spec |
|---|---|---|
| `BAD_FRONTMATTER` | no `---` block; missing `id` / `kind` / `status` / `predecessors`; unknown status; id ≠ file name; duplicate id; V- record without id / candidate / verdict | App. C |
| `ID_FORMAT` | id not `P-dddd` or `P-dddd.n` | App. B |
| `DANGLING` | predecessor not found; `conditional_on` CJ not in `conjectures.md` | 3b.3 |
| `CYCLE` | dependency cycle (reported once per cycle, on its first node) | 3b.3 |
| `PROPOSED_IN_PROPOSITIONS` / `VERIFIED_IN_CANDIDATES` | status and directory disagree | 3b.3 |
| `VERIFIED_NO_PASS` | verified node without a V- record whose `candidate` matches and `verdict: pass` (a revision may keep the original's record named in `verification`) | 3b.5, 3b.8 |
| `UNVERIFIED_PREDECESSOR` | verified node cites a `proposed` node | BAN-12 |
| `REVOKE_NOT_CASCADED` | verified node cites a revoked / superseded predecessor, a revoked A-/D-, or is conditional on a `dropped` conjecture | 3b.8, 3b.9 |
| `PENDING_AXIOM_CITED` | verified node cites an A-/D- that is pending or absent from `axioms.md` | BAN-12 |
| `UNREGISTERED_SYMBOL` | verified node's `glossary_introduces` not in `glossary.md` (candidates exempt) | BAN-13 |
| `CONDITIONAL_NOT_INHERITED` | a predecessor's `conditional_on` entries are missing from the node's own | BAN-03 |
| `CONDITIONAL_WITHOUT_GUESS` | `conditional_on` non-empty but `markers` lacks GUESS | App. C |
| `FAITHFUL_WITH_SIG` | `operationalization: faithful` but SIG (or a strengthened / extended node) sits in its support closure — `markers` lists a node's **own** marks only, so inherited SIG is found by walking the predecessors, not read from the node's header | 3b.4 |
| `FAITHFUL_WITH_CONDITION` | `operationalization: faithful` but a non-empty `conditional_on` sits in its support closure (its own or a predecessor's) — a provisional premise is not a shape present in the ratified axioms, so a conditional node is at least **strengthened**. The other half of the same rule, reported under its own code so the two are told apart | 3b.4 |
| `EXEMPT_REVISION_CHANGED` | a revision (`P-xxxx.n` with `revision_of`) that keeps the **original's** verification record — the one revision 3b.8 exempts from the gate — but differs from the original by more than the licensed swap: `conditional on CJ-xx ([GUESS])` → `by A-xx` in the Statement / Derivation (a sentence-initial capital is kept) plus the removal of that one CJ from `conditional_on`. Any other difference, or a removal of no CJ or of more than one, is a revision that must open a verifier. A revision citing a **new** V- id passed the gate on its own and is not checked by this rule | 3b.8, 3b.9 |
| `MISSING_SHA` / `STALE_SHA` | `content_sha` absent or ≠ recomputed digest, nodes in `propositions/` only (`--fill-sha` also stamps `candidates/`, so the digest is fixed before the gate) | 3b.5 |

Informational, `--report` only, never counted: `CLOSURE_NOT_CLOSED` (theorem verified but `conditional_on` non-empty, 3b.7), `SCOPE_MISMATCH` (closure ≠ unconditional verified nodes whose `scope` holds the theorem's ID, 3b.7), `DUPLICATE_SHA` (identical Statement + Derivation digest in two live nodes), `DANGLING_FIELD` (`revision_of` or `supersedes` names no node).

Bare predecessor IDs resolve to the family's highest **verified** revision, else the highest not revoked / superseded, else the highest present (3b.8); an explicit `P-0007.1` resolves exactly.

## Pre-gate codes (`--pregate` only; not counted at round start)

Candidates stay exempt in the default run; these codes are reported only for the candidates named after `--pregate`, before the gate. Two definition markers are read — `:=` (or `≔`) and bold — and nothing else: there is no general symbol scan.

| Code | Condition | Spec |
|---|---|---|
| `SYMBOL_COLLISION` | a `glossary_introduces` entry, or a term the Statement / Derivation defines with `:=` or in bold, is already a name in `glossary.md` — unless every glossary row for it was introduced by the candidate's own family (a revision re-listing its own symbol) | BAN-13 |
| `UNLISTED_DEFINITION` | a term defined in the Statement or Derivation is not in `glossary_introduces`: the token left of `:=` (for `f(x) :=` the name `f` also counts) or a `**bold**` span | BAN-13 |
| `UNLISTED_ORDER_DERIVATIVE` | the candidate introduces an order symbol (`≤ ≥ < >`, `≼ ≽ ≺ ≻`, `⪯ ⪰`, `⊑ ⊒ ⊏ ⊐`, `⊆ ⊇ ⊂ ⊃ ⊊ ⊋`, any decoration such as `≼_σ`), and its dual, strict part or inverse with the same decoration is used in the Statement or Derivation but neither listed nor registered — each counts as a symbol | BAN-13 |

## Manual checklist equivalence

Where scripts cannot run, the same list is checked by hand and the forge log says "checked by hand this round" (3b.5). The manual list is §6 of `skills/g2g-forge/references/forge-protocol.md`, 14 items, one-to-one with the codes: 1 headers well-formed → `BAD_FRONTMATTER`, `ID_FORMAT`; 2 acyclic → `CYCLE`; 3 no dangling references → `DANGLING` (+ informational `DANGLING_FIELD` for `revision_of` / `supersedes`); 4 status and directory agree → `PROPOSED_IN_PROPOSITIONS`, `VERIFIED_IN_CANDIDATES`; 5 every verified node has a passing V- → `VERIFIED_NO_PASS`; 6 only verified bricks → `UNVERIFIED_PREDECESSOR`; 7 revocations and supersessions cascaded (bare IDs resolve to the current revision — the resolver above) → `REVOKE_NOT_CASCADED`; 8 no pending bricks → `PENDING_AXIOM_CITED`; 9 glossary complete → `UNREGISTERED_SYMBOL`; 10 condition inheritance and the GUESS mark → `CONDITIONAL_NOT_INHERITED`, `CONDITIONAL_WITHOUT_GUESS`; 11 faithful means no signature → `FAITHFUL_WITH_SIG` and, for the `conditional_on` half of the same 3b.4 rule, `FAITHFUL_WITH_CONDITION`; 12 digests filled and current → `MISSING_SHA`, `STALE_SHA` (+ informational `DUPLICATE_SHA`; `--fill-sha` fills them); 13 closure test → `--report` theorem lines, informational `CLOSURE_NOT_CLOSED` / `SCOPE_MISMATCH`; 14 overview table → `--regen-index`. The pre-gate check (`--pregate`) has no by-hand equivalent: without scripts, the gate's BAN-13 check still applies.

`EXEMPT_REVISION_CHANGED` has no number in that list: the gate-exempt CJ → A- swap is checked by 3b.8's own rule, and where scripts cannot run the orchestrator compares the two revisions by hand and logs one line in the forge log.

## `cadence_check.py` — the cycle cadence check

g2g-cycle runs it every M cycles ("Select the question") and writes its first line into the log: were the last M questions all from salvage or earlier cards rather than from the queue, the plan or the Vision? It only steers — it never stops a run — and it needs no `07_theory/`.

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/cadence_check.py" g2g          # the form g2g-cycle uses; cwd = the user's project root
python scripts/cadence_check.py <workspace> [--json] [--m N] [--version]
```

`<workspace>` is the `g2g/` folder or the folder containing it. It reads three files: `00_programme.md` for M (the `M = n` on the macro-audit line; 4 when there is none); `04_log.md` for the last M `CYCLE #n · question Sk` keyword lines (a cycle logged more than once — paused, then resumed — counts once); `02_question-registry.md` for each of those questions' seed row (the lines that start with its ID). A seed row's source: `[source: salvage]` or `[source: card C-xxx]`, and on rows written before the tag the markers `parent:` / `父：` / `SALVAGE` / `打捞` → from salvage or an earlier card; `[source: queue]`, `[source: plan]`, `[source: vision]` → not; anything else, a missing row included → "source unknown", never counted as salvage. Output: line 1 is the verdict, for the orchestrator to copy into the log — `Cadence (M = 4): the last 4 questions all came from salvage or earlier cards — steer: draw the next question from the queue, the plan or the Vision.`, or `… were not all from salvage or earlier cards (salvage or cards a · queue, plan or Vision b · source unknown c) — no steer.`, or `… n cycle(s) in the log, fewer than M — no verdict.` — then one line per question, `#n · Sk · class · evidence` (never starting with `CYCLE #`, so a copied line is not read as a cycle). `--json` gives the same as one document; `--m` overrides M (testing); nothing is written. Exit codes: `0` no steer (or no verdict), `1` steer, `2` usage / IO error (no `04_log.md` or no registry). Where scripts cannot run, the orchestrator reads the sources of the last M questions in the registry by hand.

## `upgrade_workspace.py` — the settings upgrade of a 0.3.0 workspace

g2g-go runs it at preflight (Step 0, item 5), only when items 1–4 passed and scripts can run: first `--check`, then — when an upgrade is due — the same command without it (attended: unless declined in the single question; unattended: at once). Where scripts cannot run there is no upgrade, and the first line of the handoff notes says so in one sentence.

```
python "${CLAUDE_PLUGIN_ROOT}/scripts/upgrade_workspace.py" g2g --check   # g2g-go preflight: detect only, writes nothing
python "${CLAUDE_PLUGIN_ROOT}/scripts/upgrade_workspace.py" g2g           # upgrade
python scripts/upgrade_workspace.py <workspace> [--check] [--json] [--version]
```

`<workspace>` is the `g2g/` folder or the folder containing it. The script changes only recognised, mechanical 0.3.0 forms, and any one of them makes the upgrade due. In `00_programme.md`: the pre-authorized-defaults rows keyed `round_token_budget_estimate` and `period_share` are deleted (the keys are matched in English, as every charter writes them); the 0.3.0 tiering table — headed by the three tiers, English or Chinese role names, cells `inherit` / `opus` (or the methodology's "inherited" / "next-strongest tier", 继承 / 次强档), another model alias, or "—" — becomes the new table with cells mapped by role, not by line (old "Deducer" → "Deducer — new derivation"; the three rows 0.3.0 lacks take their defaults; a cell the project changed is kept, and a kept cell that differs from the new table is listed); every sentence that permits moving an agent one tier up or down for remaining budget or quota — the 0.3.0 English forms, and localized sentences naming both, such as 上下调一档 with 剩余额度 / 余额 / 预算余量 — is struck as `~~…~~ (void from G2G 0.4.0: tiers follow the table; no tier changes for quota once a run starts)`, while a sentence already struck or a prohibition is left alone; the 0.3.0 budget-fence paragraph (one line, beginning "Budget fence (the boundary of unattended operation is usage, not a permission gate): the orchestrator counts every agent call") is replaced by the new one, and a charter without one gets none; the dispositions rows "Budget at 80%" / "Budget at the ceiling" (and rows like 预算到 80% / 预算到顶) become the two usage rows. In `01_hard-core.md`: the 0.3.0 U-series title, or a localized title naming the U series and the objection classes the human closed, is replaced and the rule line put under it; the old table, entries and scopes stay. In `06_process-defects.md`: the nine rules the 0.3.0 template seeded are deleted where they still read word for word, with any heading they leave empty. When it upgrades anything it also sets the charter's `Methodology: G2G v3.0` to v3.1. Not touched: the question-selection cell, a submission-cap cell still reading "[to be filled …]", `05_plans/decision-bar.md`, old seed rows. The inserted blocks are the text of `skills/g2g-setup/references/templates.md` (a test keeps them equal).

Before its first write to a file it copies that file to `<name>.v0.3.0.md` beside it (`00_programme.v0.3.0.md`, `01_hard-core.v0.3.0.md`, `06_process-defects.v0.3.0.md`) — once; an existing backup is never overwritten. A second run changes nothing and makes no second backup. The report: line 1 is the summary for the first line of the handoff notes — what changed, the backups, how many items were left as is; then one `left as is · <file> · …` line per form it did not recognise (a tiering table of another shape, a tier row or cell it cannot map, a tier sentence without a quota word, another fence paragraph, another budget row, another U-series title, seeded rules in other words) and per kept tier cell that differs from the new table; then `deleted · <file> · <line>` with the full text of every deleted line that held more than the template's own text (a budget row the human filled in, a localized title). With nothing due it prints line 1 alone. `--check` prints the same report and writes nothing (the deleted lines marked `to delete`); `--json` gives it as one document. Exit codes: with `--check`, `0` current, `1` upgrade due; without it, `0` upgraded (or nothing to do), `1` upgraded with items left as is; `2` usage / IO error (no `00_programme.md`, a file that is not UTF-8), and nothing is written. Line endings and a BOM are kept as found.

## File conventions the parsers rely on

Node frontmatter: `key: value`, lists as `[a, b]`, `# comments` allowed after a space; sections `## Statement`, `## Derivation`, `## Falsification surface`, `## Notes`. `scope:` holds the target theorem's ID. A revocation is written `revoked_by: <category> · <reason> · <date>` and a revision `revision_of: P-xxxx · <category>`, the category one of `gate-miss` (the node's own derivation was wrong and the gate let it through, whoever found it later), `cascade` (something it rests on fell: a predecessor, an A-/D-, a conjecture, a rejected I- reading), `human-ruling` (the human replaced or rejected it directly), `mechanical` (wording, format or reference numbers only, or the gate-exempt CJ → A- swap); none written counts as `uncategorised`. `axioms.md` / `conjectures.md`: one entry per line (bullet, bold, table row or `##` heading) starting with the ID; the status is the first status word after `status:` (or after the ID) — `RATIFIED / PENDING / REVOKED` (also 已批 / 待批 / 撤销) and `open / promoted / ratified / dropped`. `glossary.md`: first column of a table (header row skipped) or `- symbol · …` bullets; backticks and `$` are ignored; a literal pipe inside a table cell is written `\|`; a trailing parenthetical note is ignored — a full-width `（…）` always, an ASCII `(…)` only after a space, so `𝒫 (power forms)` reads as `𝒫` while `f(x)` stays `f(x)`; the "introduced by" column (its header says so, else the fourth column) tells `--pregate` which family registered a name. V- records: frontmatter `id`, `candidate` (first `P-` token is used), `verdict`. The registry and the log are read by `cadence_check.py` (its section above).

**Keys that stay English whatever language the files are written in** — the scripts and skills parse them; translate the text around them, never the keys: node frontmatter keys (`id`, `title`, `kind`, `status`, `empirical_status`, `layer`, `scope`, `predecessors`, `axioms_used`, `definitions_used`, `assumptions_used`, `external_refs`, `conditional_on`, `glossary_introduces`, `operationalization`, `markers`, `interp_pending`, `verification`, `supersedes`, `revision_of`, `revoked_by`, `content_sha`, `submitted_by`) and their fixed values (statuses, kinds, operationalization tags, markers, reason categories); the four node headings above; V- record keys `id`, `candidate`, `verdict` and the verdict `pass`; forge-log titles `## Round n` and the "Submitted" line (`a / b / c`); the keyword lines of `04_log.md` (`FORGE round n`, `CYCLE #n · question Sk`, `PLAN vNNN`, `STATUS`, `SETUP`, `READ-ONLY`, `preflight:`) and the run lines `RUN open`, `resume:`, `RUN closed`; the registry tag `[source: queue | plan | vision | salvage | card C-xxx]`; in the charter, `modes:`, `builds_math_system:`, the `key` column of the pre-authorized defaults (`unattended`, `question_selection`, `severity_tier`, `card_disposition`, `interp`, `critic_collision`, `forge_scope`, `outward_actions`, `submissions_per_round_cap`), `M =` on the macro-audit line, and the forms the upgrade script recognises (its section).

- Never put a README or any other non-node `.md` inside `candidates/`, `propositions/` or `verifications/` — every `.md` there is parsed as a node or a verification record; use an empty `.gitkeep` to keep empty folders.

## Tests

```
python -m pytest -q scripts/tests
```

Run from the plugin root (the test classes are `unittest` classes; pytest collects them). `scripts/tests/` — tests and fixtures, all fictional — stays in the GitHub repository and is not packed into the `.plugin`.
