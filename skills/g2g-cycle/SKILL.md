# G2G Cycle

Orchestrate one complete research cycle. Read `g2g/00_programme.md`, `g2g/01_hard-core.md`, and `g2g/02_question-registry.md` before anything else. Note the programme's severity default (the user may override for this cycle) and the standing-rulings register. If `g2g/` does not exist, stop and run g2g-setup.

## Anti-dogma rules (highest priority, enforce mechanically)

- **R1 Rotation, two axes.** Do not use the same theoretical-framework family in two consecutive cycles — and do not use the same **data domain** either (two consecutive cycles in one data domain is a documented, independent way to ossify). Record family AND domain in the registry genealogy. If the user insists on repeating, comply and log a waiver.
- **R2 No re-cutting.** Check the registry; a registered question may not be cut again. Derived questions must name their parent and the new increment.
- **R3 Cross-level linkage.** A conclusion that cannot fill the card's "Framework linkage" field is void.
- **R4 Mechanism first.** Each cycle must propose at least one cross-level mechanism (behavior at one layer → consequence at another). Describing preference differences is not a mechanism.

## Phase sequence

**Select the question.** Prefer user's explicit pick; otherwise propose 2–3 candidates from registry seeds (passing R1/R2 on both axes), with the expected cross-level mechanism in one sentence each, and let the user choose.

**P1 Reconnaissance — pick the mode.** *Full sweep* (fresh subagent) for cycle 1 or a new domain; *incremental* (default): update `03_records/literature-ledger.md` — new neighbors and stale entries only, since the novelty critic searches again at tribunal time; *delegated* (exploratory severity): fold into the novelty critic entirely. All modes: sweep on **two axes** (method family × application domain — single-axis sweeps miss nearest neighbors), and answer the gate: *is this already done, deeper?* If yes → learning mode: write a learning note into `03_records/`, register the question as covered-by-literature, and end the cycle. If no → proceed with the stated increment, and write it down as the **pre-coded novelty claim** the tribunal will grade.

**P2 Formalization — multi-operationalize.** Translate the relevant slice of the vision into propositions: operationalized definitions (measurable), directional claims. For each core intuition of the human (or an external collaborator — same rule), produce **at least two operationalizations side by side** — most-faithful and strongest — each tagged faithful/strengthened/extended. Mark every shape added beyond the source narrative with `[SIG]`. Run **carrier checks** on institutional anchors (verify the named channel/instrument actually carries what the argument needs; leave a verification note). Propose 2–3 candidate framework skeletons from the rotation menu with trade-offs — never default to the previous cycle's family (R1).

**P3 Axiom check.** Use the ratified hard core and the declared-assumptions list. Any new axiom the deduction would need goes to `01_hard-core.md → Pending axiom proposals` for user ratification — do not smuggle it in. Load the standing rulings; they ride along to every downstream agent.

**P4–P5 Conjecture and parallel deduction.** Spawn **N `g2g-deducer` agents in parallel** (N by severity: exploratory 1 / standard 2 / submission 3), each in a fresh context, none aware of the others, each receiving: hard core, declared assumptions, the full multi-operationalized proposition set, skeleton, and the output contract (falsification-surface inventory first; ≥4 non-trivial conclusions, ≥2 cross-level; every guess `[GUESS]`; every added shape `[SIG]`; self-assessment). Never deduce in the orchestrator's own context. **Merge protocol:** first **freeze** the independent briefs; then build a divergence list (who derived what others missed; who contradicts whom — divergence is information, record it in the contradiction log); send each deducer the list only, taking responses as **marked amendments** with the frozen originals preserved for the tribunal; then consolidate into a single deduction brief. Independence governs generation; exchange happens only after every brief is frozen.

**P6 Tribunal.** Spawn the three critic agents in parallel, each in a fresh context, each seeing only: axioms, declared assumptions, rulings register, severity tier, and the deduction brief (never each other): `g2g-logic-critic`, `g2g-evidence-critic`, `g2g-novelty-critic`. Enforce the tier's quotas (with the escape valve: a critic that cannot reach quota with receivable objections says "receivable surface exhausted" — fabricated objections are forbidden); no endorsement; no fix suggestions. **Exemption rule:** attacks on declared assumptions arrive tagged `LOGGED (exempt)` — append them to the silent ledger in `01_hard-core.md`, uncounted, unlitigated. Then the defense: at exploratory severity, return objections to a deducer (continue its context if the platform allows); at standard, offer the independent `g2g-defender`; at submission, the defender is **mandatory, with the programme's data file paths and the recomputation obligation**. Defense verdicts: defended / partly defended / conceded. **Adjudicate critic collisions provisionally**, record them, and surface them in the verdict — the human can re-decide any collision on review. Max rounds per tier; unresolved → escalate to the user.

**Verdict assembly.** The written verdict (to `03_records/`, template in g2g-setup references) uses three-value language — **alive / dead / undecidable (+reason)**; "not detected" never becomes "refuted". It contains: the **sentence-level kill table with replacement language** (patrol the five overreach verbs: confirm, guarantee, falsify, vindicate, co-move) — this table is the binding wording baseline for all downstream writing; **cross-proposition registration** (what other propositions each major number could support or refute); numbered **defense pieces**; collisions; attacks-on-core log lines.

**P7 Grounding.** For each surviving conclusion, answer three questions: What observable prediction? What data pattern would refute it? Has history already run the experiment (name it)? Unrefutable claims are decoration — mark them so. Where results will enter a frozen registry, attach a **programmatic reconciliation list** (machine-checkable sample counts and ranges).

**P8 Score, record, hand off.** Score on **five axes** (internal consistency / empirical compatibility / falsifiability / novelty / **sellability** — one contribution, venue-shaped, retellable in two sentences), 1–5 each, against the charter's pass line (default ≥18/25, falsifiability ≥3, sellability ≥2). **Scores inform; the human disposes:** below the line defaults to *archived-in-progress* with explicit **re-scoring triggers** written on the card; demotion or burial is the user's call, never automatic, and never grounds for piling on objections. Write the conclusion card, append contradiction-log entries **as they occur, not at the end**, update the registry (both genealogy axes; harvested seeds — tribunal SALVAGE goes to the seed registry, mandatory), log attacks-on-core, update `04_log.md`. Stop rule: two consecutive rounds without score improvement = converged; budget exhaustion = archive as stalled (a constraint, not a quality signal).

## Verdict to the user

Open with a **plain-language digest** (3–5 sentences, no internal jargon): what died, what survived, what it means. Then ≤10 lines of specifics: kill list (and to whom), exact surviving sentences, scores, framework linkage. Close with a **decision bar in the four-line format** (what was done / what you must decide / default "takes effect unless changed" / cost of not deciding), each item annotated with **what it blocks**. The user reviews the tribunal record — offer it, don't paraphrase it away. If the platform makes follow-up cheap, offer a separate learning session for anything the user wants explained — teach-back is part of delivery.

## Failure modes to actively resist

Sycophancy and critic convergence (quotas + fresh contexts); a polluted hard core (fact-check before ratification); path-dependent deduction (parallel deducers, late merge); naive signatures (multi-operationalization + `[SIG]` — when something dies, name whose addition it was); over-negation (exemption rule + severity dial — the target is execution, not the human's premises); context drift (state lives in files, one round per context); narrative overfitting (grounding is mandatory); human rubber-stamping (surface the tribunal log, not just the card); token blowups (one session, one cycle; hand off at stage boundaries).
