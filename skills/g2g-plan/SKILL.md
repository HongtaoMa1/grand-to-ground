# G2G Plan

The versioned research plan is the steering wheel of a G2G programme: it translates tribunal verdicts (and, in a Forge programme, the state of the proposition graph) into next actions, carries the human's approvals, and briefs whoever executes. This skill writes and iterates plans in `g2g/05_plans/` (`plan-v001.md`, `plan-v002.md`, …). Requires an initialized `g2g/` workspace; without one, offer to run g2g-setup or produce a standalone plan using the same anatomy. The one-line entry ("run G2G") is g2g-go's; it routes here when a plan is awaiting freeze.

## Step 1 — Read the state

Read, in order: `00_programme.md` (charter, severity, ID legend, collaborator, programme modes, pre-authorized defaults), the highest-numbered plan in `05_plans/` (its approval record at the file end is the baseline — never renumber or reinterpret recorded approvals; a decision pack beside it holds the human's handwritten answers to heavy items), the latest tribunal verdict(s) and cards in `03_records/` (the substitution tables there are the **binding wording baseline**; TT verdicts carry empirical-status suggestions and disposition items), and `02_question-registry.md` (seeds and genealogy for offense candidates). If `07_theory/` exists, also read `graph-index.md` (verified skeleton), the latest `guidance.md` entry (scope as the human set it, live / parked / abandoned routes), the latest elaboration (frontier, missing bridge lemmas, `[INTERP]` queue), `dead-ends.md` (what not to plan again), and `forge-log.md` (cadence due, budget account) — these are the inputs for Forge milestone lines.

## Step 2 — Draft plan vN+1

Anatomy, in this order:

1. **Header** — version, date, status (`draft — awaiting ticks`), inputs (which verdicts/rulings/feedback/graph state this version digests).
2. **Plain-language digest (§0)** — half a page the human reads first. No internal jargon, no IDs without a gloss. What happened, what this version changes, what they need to do. Write it last, place it first.
3. **Module lines, tick-to-approve:**
   - **Repair line R1…Rn (mandatory):** one module per accepted tribunal finding. **Self-containment rule:** every module that responds to an objection carries a one-line plain restatement of that objection — *"R3: (critic found the control window overlaps the event window, so the placebo is contaminated) → re-draw windows disjoint."* A plan that says "fix per L8, see tribunal file" has outsourced its own comprehensibility; the human must be able to review without a decoder. In a Forge programme, a TT disposition item the human has answered ("add declared assumption DA4") becomes a repair module too; a cascade-revocation rebuild list becomes one module per affected branch.
   - **Offense lines A/B/C… (optional):** from tribunal salvage and registry seeds, each with its expected cross-level mechanism in one sentence and its rotation-compliance note (both axes). **Forge milestones as offense lines (v3):** in a programme with the Forge open, an offense line may be a Forge goal — "prove the micro layer's target theorem P-0031", "close branch B (bridge lemma between P-0012 and P-0020)", "settle conjecture CJ-03 by pushing both maps" — stated with the human-set **scope** it runs under, the rounds budgeted, and an **acceptance criterion that is not a card score**: the target theorem's support closure closes (verified, `conditional_on` empty), or the closure grows by the named bridge, and/or the theory tribunal's outcome (TT-NN: grounded / contested / refuted-in-data on the named nodes). Node counts are never an acceptance criterion — busyness is not progress. A Forge line never widens the scope on its own; a scope change is itself a decision for the bar.
   - Every module gets a tick box. Approval is a tick: "R1 ✓ R2 ✓ A skip" completes review.
4. **Decisions at two speeds (v3).** Sort every open decision light or heavy with one test: *if, after reading the four lines, the human would still have to ask "what is this, and why", it is heavy.*
   - **Light → decision bar**, every item in the **four-line format**: *what was done* (one sentence of context) / *what you must decide* (a concrete choice, never an open question) / *default* ("takes effect unless changed", genuinely executable) / *cost of not deciding* — plus a **blocks** column naming what stalls while it waits. Three prohibitions: no "see §X" pointers that make the human fetch context; no missing defaults; no undefined jargon inside a decision item. Adequacy standard: decidable from this screen alone. `[INTERP]` rulings (I-numbers, each with the sentence and the reading proposed), "requires new axiom" items (pending A-/D- IDs with their one-line statement and source), and conjecture dispositions are usually light.
   - **Heavy → decision pack**, written to `05_plans/plan-vNNN-decision-pack.md` (NNN = this plan's version; one pack per plan version, several heavy items may share it — the same file g2g-cycle and g2g-tribunal write to between plan versions) using the **decision-pack template in g2g-setup's `references/templates.md`** — do not re-invent the format here. Its shape, for orientation only: one storyline (where the matter came from, why it must be decided now) → per item: terms taken apart, consequences on each side, a recommendation with reasons (facts and guesses marked separately), an entry point for checking it oneself → at the end the four-line bar plus a blank the human fills in by hand. The plan's decision bar carries one line per heavy item pointing at the pack ("H1 · which carrier for the flow variable → decision pack, item 1") instead of forcing it into four lines. The adequacy standard is the same as the bar's — the human can fill it in without asking the AI anything more; the difference is that it admits understanding takes time and prepares the material for that time. A heavy question thrown at the human as a bare question is a defect.
5. **Frozen-wording appendix** — sentences this plan carries forward from verdicts, quoted exactly from the substitution tables (qualifiers included). The plan may compress logistics, never wording.
6. **Approval record (file end)** — dated ticks and rulings as the human writes them, plus the pack's filled-in blanks copied over verbatim once written. Append-only.

## Step 3 — Version discipline

- Generating vN+1 triggers the **archive prompt**: list vN's handover items (task briefs, start prompts, decision pack) that should move to the executed round's directory, and remind the human. Do not delete anything yourself.
- **Entry files never name versions.** If the project's `CLAUDE.md` (or equivalent) references plans, the phrasing is "highest version is current" — a hard-coded round number in an entry file once silently pointed a whole execution round at the previous round's spec.
- IDs follow the programme legend (`00_programme.md`); new series must be registered there first. Revisions use dotted numbers (R2.1), never accumulated primes. Cross-document references carry the scope word ("plan R2", "node P-0005", "offense line A", "axiom A-01").

## Step 4 — The plan tribunal gate

Before a plan's propositions enter a frozen registry, or the plan (or any material derived from it) goes to an external collaborator: **the plan stands tribunal** — invoke g2g-tribunal in plan mode (ST series). The target is the new shapes and mappings this plan adds (formalizations, framings, outward translations), not the frozen results it cites. The ST includes its fixed **qualifier-fidelity audit** step (Step 5 below runs the same audit at generation time; the ST's pass is the independent gate). Exemptions: purely editorial revisions (wording, layout) don't trigger; a small change to an already-tried plan (no new shapes) doesn't trigger, but is logged. Field record: the first plan tribunal found fourteen dead sentences, all in the translation layer — the gate exists because that layer had no other guard. Anything outward-bound is submission-tier by definition.

## Step 5 — Collaborator materials (when the charter names one)

- **Clean author context (v3).** Outward products — the one-page brief, the call notes, a paper section — are rendered by a **fresh, isolated agent** that has never seen the programme: spawn a general-purpose subagent with no G2G files, fed only a **de-jargonised input pack** this seat prepares first: the results sentences in frozen verdict wording (qualifiers intact), nulls, caveats, data gaps, assumptions stated as assumptions, the collaborator's professional terminology and the audience, the structure wanted. The pack contains **no** IDs of any series (R, S, C, DP, ST, TT, P-, CR-, I-), no node IDs, no dead sentences or kill tables, no defense pieces, no tribunal narrative, no internal pet names. An author that has never seen the words cannot leak them — this is the mechanical guarantee of discipline invisibility, not a request for restraint.
- **One-page brief:** the plan's story in the collaborator's professional language — **standard field terminology only**; internal pet names never leave the building. Every results sentence passes the **step-down rule**: aligned sentence-by-sentence with frozen verdict wording, qualifiers intact.
- **Qualifier-fidelity audit — run on every outward material, every time (v3).** After rendering, align each outward sentence with the frozen verdict sentence it descends from, sentence by sentence, and list the **lost qualifiers** ("verdict: 'within the sample period'; brief: absent"). A non-empty list goes back to the clean-context author as corrections (never patch by pasting internal wording yourself — that re-opens the leak), then re-audit. Nothing leaves the building until the list is empty; the ST gate (Step 4) re-runs the audit independently. Record the audit's result (sentences aligned / qualifiers restored) in the plan's inputs section.
- **Call notes card:** the questions to ask, the answers to have ready (including the standard answer to any question previously fumbled), decisions wanted from the call. Same clean-context rendering, same audit.
- **Rulings archive:** after contact, record the collaborator's decisions *verbatim and dated* in the plan's inputs section (and as standing rulings if they are standing) — collaborator rulings are argued with the human, never silently re-litigated by agents. A collaborator's spoken story receives the P2 treatment when formalized: multi-operationalization, `[SIG]` marks, `[INTERP]` marks on every reading of their words (queued for the human, who arbitrates on the collaborator's behalf) — their intuition has the same rank as the user's; the signature dies, not the story.
- **Discipline invisibility:** outward materials never showcase the internal machinery (frozen registries, tribunals, substitution tables, the proposition graph) — results, nulls, caveats, and data gaps are reported in full; process narrative is not. When a Forge milestone is written up, cut it by the convergence principle — one theorem or mechanism that can stand as a paper on its own, with its closure — and score sellability then, as usual. **Red line: a test added after results were known is never described outward as pre-specified. "Not saying" ≠ "saying the reverse."**

## Plan-first mode

On request ("plan-first", "no empirics yet", or a collaborator gate in force): iterate plan → digest → human/collaborator feedback → plan vN+1, with no empirical execution, until the frame is agreed. Each iteration still passes Step 4 before going outward. Cheaper than running studies nobody has agreed to want. A Forge programme's equivalent is scope-first: agree the layer and target theorem in the plan before spending rounds.

## Handoff

End every run with: the digest, the tick list, the decision bar (with blocks) and the decision pack if any heavy item exists, and — if an execution seat exists — the handover kit per `references/collaboration-protocol.md` (which now carries the pre-authorized defaults, the unattended dispositions, the script-availability line, and the budget line). One session, one plan version; write the state, then stop.
